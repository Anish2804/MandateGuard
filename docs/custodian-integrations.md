# MandateGuard — Enterprise Custodian & Wallet Provider Integrations

## Executive Summary

Enterprise AI payment systems cannot rely on raw private keys stored in plaintext `.env` files or backend databases. In accordance with **Requirement 9** of the MandateGuard specification, this document analyzes four enterprise custody and smart-wallet architectures:
1. **Turnkey (Passkey/MPC)**
2. **Fireblocks (Vault/TAP)**
3. **Privy (Embedded & Server Wallets)**
4. **Coinbase Developer Platform (CDP Server-Signer)**

To preserve audit integrity, all adapters in the MandateGuard repository are implemented as **demonstrated, tested mock adapters** (`backend/app/adapters/custodian_adapters.py`) with `is_mock = True`. No mock is represented as a live production integration.

## 1. Provider Architectural Matrix

| Provider | Core Model | Auth Mechanism | Signer Role in MandateGuard | Production Enclave / Boundary |
|---|---|---|---|---|
| **Turnkey** | MPC (Threshold ECDSA) with AWS Nitro Enclaves | WebAuthn / P-256 Stamp Headers (`X-Stamp-Header`) | Authorizer Signer (Verdict signature) or Account Owner | Ephemeral enclave session, client passkey authentication |
| **Fireblocks** | MPC-CMP (Multi-Party Computation) | REST API with RSA-4096 request signing + TAP policies | Institutional Authorizer (Quorum approval of mandates) | Multi-cloud SGX/Nitro enclaves, TAP rule engine |
| **Privy** | Shamir secret sharing / Embedded Wallets | Server auth token + authorization keypair | End-user mandate management & agent delegator | Distributed HSM shares + user-authorized session tokens |
| **Coinbase CDP** | WaaS (Wallet-as-a-Service) MPC | CDP API Key + EC private key signing | Agent funding wallet or smart account authorizer | Coinbase hardened MPC infrastructure |

## 2. Deep-Dive: Turnkey Integration

### Architecture
Turnkey manages cryptographic keys within AWS Nitro Enclaves. Every request to Turnkey must be accompanied by an `X-Stamp-Header` containing a P-256 signature generated by a credential registered in that organization or sub-organization.

### MandateGuard Integration Model
In MandateGuard, the **Authorizer Key** (the key that signs `PaymentVerdict` EIP-712 digests) can be hosted inside a Turnkey secure enclave:
1. When an agent requests payment authorization (`/api/v1/authorize`), the backend checks the spending mandate.
2. If allowed, the backend constructs the EIP-712 `PaymentVerdict` message and computes its 32-byte digest.
3. The backend signs the HTTP request payload using its Turnkey API stamp key.
4. Turnkey enclave signs the 32-byte digest using the authorizer's threshold ECDSA key and returns `(r, s, v)`.
5. The signature is attached to the verdict returned to the agent.

### Production Prerequisites
- Turnkey Organization ID & Sub-Organization provisioning.
- API Keypair (P-256) registered with administrative permissions.
- Turnkey Python SDK or direct HTTP client to `https://api.turnkey.com`.

## 3. Deep-Dive: Fireblocks Integration

### Architecture
Fireblocks provides institutional custody where transactions are subject to a **Transaction Authorization Policy (TAP)**. RAW signing allows signing arbitrary hashes without broadcasting to the blockchain.

### MandateGuard Integration Model
1. High-value spending mandates ($100k+ enterprise mandates) can require a Fireblocks vault signature.
2. The authorization service submits a RAW signing operation:
   ```json
   {
     "operation": "RAW",
     "source": {"type": "VAULT_ACCOUNT", "id": "1"},
     "extraParameters": {
       "rawMessageData": {
         "messages": [{ "content": "<EIP-712_DIGEST_HEX>", "bip44addressIndex": 0 }]
       }
     },
     "note": "MandateGuard EIP-712 PaymentVerdict Signing"
   }
   ```
3. Fireblocks TAP enforces multi-person quorum approval for the mandate authorizer key before the signature is released.
4. The signed verdict is verified onchain by `MandateGuardAccount.sol`.

### Production Prerequisites
- Fireblocks API user and RSA private key (`.key` file).
- Configured Vault Account with BIP-44 key index.
- Production webhook listener for asynchronous RAW transaction status updates.

## 4. Deep-Dive: Privy Embedded Wallets

### Architecture
Privy allows non-custodial wallet creation for human users via passkeys, email, or social login. User keys are split into Shamir shares (device share, auth share, recovery share).

### MandateGuard Integration Model
1. The **Human Owner** of `MandateGuardAccount` connects via Privy in the web dashboard.
2. The user signs the `registerMandate(...)` transaction using their Privy embedded wallet.
3. Privy's Server Wallets API can also hold the AI agent's dedicated session key to sign execution transactions, ensuring the human owner's master key is never exposed to the agent backend.

---

## 5. Deep-Dive: Coinbase CDP

### Architecture
Coinbase Developer Platform (CDP) provides MPC wallet-as-a-service through server-side Python and TypeScript SDKs.

### MandateGuard Integration Model
1. Agents provision ephemeral CDP MPC wallets.
2. Agent requests authorization from MandateGuard.
3. Upon receiving the signed verdict, the CDP wallet broadcasts `executePayment(...)` to the Base Sepolia RPC.
